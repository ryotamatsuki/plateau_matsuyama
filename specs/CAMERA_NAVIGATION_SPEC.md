# 松山3Dハザードマップ カメラ・ナビゲーションUX仕様

Status: **Canonical implementation specification**  
Version: 1.0  
Target repository: `ryotamatsuki/plateau_matsuyama`

## 1. 目的

松山3Dハザードマップに、地上視点と空中・俯瞰視点を高速かつ連続的に切り替えるナビゲーションを導入する。

目標は、単なる視点プリセット切替ではない。地面から離陸して高度を上げ、街区全体を俯瞰し、見ている地点へ再び降下してそのまま地上移動を継続できる、一体的な3D GIS操作体験を実現することである。

同時に、既存の「防災ウォーク」の操作感を改善し、松山城3D散歩と同等以上の軽快さ・入力応答性を確保する。

防災情報、PLATEAU建物、地形、ハザードレイヤ、建物リスク表示等の既存機能・意味・出典は変更しない。

## 2. 現状と基準

現行アプリはCesiumJSで構成され、`docs/app.js` が主要地点への `flyToBoundingSphere`、俯瞰表示、PLATEAU建物・ハザード等を管理し、`docs/walk-mode.js` が地上歩行を管理している。`docs/immersive-gis.js` では移動中と停止時で3D Tilesの `maximumScreenSpaceError` を切り替える最適化が既に入っている。

現行の防災ウォーク速度は概ね通常 `2.2 m/s`、高速 `4.2 m/s`。比較対象の松山城3D散歩は通常 `2.3 m/s`、Shift時 `4.0 m/s` であり、名目速度自体は既に近い。

したがって、本改修では速度の数値だけを上げるのではなく、以下を総合的に改善する。

- 入力から移動開始までの遅延
- カメラ追従の即応性
- モバイルスティックのデッドゾーン・スロットル特性
- 地形追従処理が移動をブロックしない構造
- 移動中の3D Tiles描画負荷
- 地上・空中・俯瞰の状態遷移
- 遷移終了直後に即座に操作できること

## 3. ナビゲーションモード

内部状態として最低限、次の3モードを明示的に持つ。

### 3.1 Ground

地表付近を移動するモード。既存の防災ウォークを基礎とする。

- 一人称・三人称の既存切替は維持する。
- 地形追従を維持する。
- 通常移動の初期目標値は `2.8 m/s`。
- 高速移動の初期目標値は `5.0 m/s`。
- PCのWASDは押下したフレームから最大通常速度を使用し、不要な加速待ちを設けない。
- モバイルはスティック倒し量に応じた連続速度とするが、全倒し時はPCと同一の最大速度に到達する。
- モバイルのデッドゾーンは必要最小限とし、中心から少し動かしただけで明確に反応すること。
- 地形標高の非同期取得は移動処理を停止させない。最後に確定した地表高を使用しつつバックグラウンドで更新する。

速度値は実機QAで微調整してよい。ただし松山城3D散歩より遅く感じる設定に戻してはならない。

### 3.2 Flight

GroundとOverviewをつなぐ中間モードであり、遷移中の内部状態として必須とする。

任意で自由飛行操作も提供してよいが、最低限、GroundからOverviewへ上昇する飛翔とOverviewからGroundへ降下する連続カメラ運動を担う。

- 遷移中に地上歩行側とCesium標準カメラ操作が同時にカメラを書き換えないこと。
- ユーザー入力で遷移をキャンセルした場合、現在位置から破綻なく適切なモードに移行すること。

### 3.3 Overview

街区・市域を俯瞰するモード。

- 斜め俯瞰を基本とする。
- 既存の真上表示は残してよい。
- パン、回転、ズームが軽快であること。
- ハザード、建物色、3D浸水等の既存レイヤ状態を保持すること。
- Overviewから「現在見ている地点へ降りる」操作を提供する。

## 4. 地上→俯瞰の飛翔遷移

### 4.1 操作

ユーザーがGroundで「俯瞰へ」または「飛ぶ」を実行すると、現在位置を基準に離陸する。

PCでは `F` キーを地上・俯瞰トグルの標準ショートカット候補とする。モバイルでは親指で押しやすい単一の主要ボタンを提供する。

### 4.2 視覚挙動

単純な瞬間切替は禁止する。次の印象を満たすこと。

1. 現在の地上位置からまず上方へ抜ける。
2. 上昇しながら徐々に視線を下向きへ倒す。
3. 現在地点周辺を中心に保ったまま高度を上げる。
4. 最終的に松山市街を把握しやすい斜め俯瞰へ入る。

標準遷移時間は `0.9–1.3 s` を目安とする。初期値は `1.05 s`。

開始時のheadingを原則維持し、突然方角を反転させない。pitchは現在値から最終 `-60°〜-75°` 程度へ滑らかに補間する。

高度は現在地点の地形高に対する相対高度で扱う。標準の最終相対高度は `350–700 m` 程度とし、画面サイズ・現在ズーム・対象範囲に応じて調整してよい。

軌道は「垂直にだけ上がって最後に角度が変わる」形ではなく、上昇・pitch変更・必要な水平後退を同時に補間し、飛翔感を出す。

イージングは `CUBIC_IN_OUT`、`QUARTIC_OUT` 等の滑らかな非線形補間を使用する。開始・終了の速度が唐突にならないこと。

## 5. 俯瞰→地上の降下遷移

### 5.1 着地点

Overviewで「地上へ」「降りる」を実行した場合、原則として画面中央の地表位置を着地点とする。

優先順位は次のとおり。

1. Cesium sceneのdepth/terrain pickで得られる画面中央の地表位置
2. globe pickで得られる位置
3. 最後に有効だったフォーカス地点

PLATEAU建物の屋根を着地点として地上歩行を開始してはならない。最終着地点は地形面へ解決する。

### 5.2 視覚挙動

- 標準遷移時間は `0.8–1.2 s`、初期値 `0.95 s`。
- headingは可能な限り維持する。
- pitchを俯瞰角から地上視点へ起こしながら降下する。
- 最後の数十mで減速し、着地直前に瞬間移動しない。
- 最終フレームまでにGround側の `lon / lat / ground / heading / cameraHeading` 等の状態を同期する。
- 着地完了直後の次フレームからWASDまたはモバイルスティックで移動できること。

## 6. カメラ所有権と状態管理

本改修で最も重要なのは、複数モジュールが同時にカメラを書き換えないことである。

新しいナビゲーション制御層を設け、少なくとも次の状態を一元管理する。

```text
GROUND
TRANSITION_TO_OVERVIEW
OVERVIEW
TRANSITION_TO_GROUND
```

推奨実装は `docs/navigation-controller.js` の新設である。既存構成により別名・統合実装としてもよいが、責務は明確に分離すること。

Ground中のみ `walk-mode.js` がフレーム単位のカメラ更新を所有する。Overview中のみ通常のCesiumカメラ操作を有効にする。Transition中はnavigation controllerだけがカメラを所有する。

`app.js` の既存 `top` 操作や主要地点移動は、新controllerと競合しないよう統合する。

`walk-mode.js` には必要に応じて次のような明示APIを追加する。

- 現在の歩行位置・向き取得
- カメラ更新の一時停止
- 指定地点・向きでGroundを再開
- active/view状態の取得

グローバルAPIを設ける場合は `window.MatsuyamaNavigation` / `window.MatsuyamaWalk` 等、既存の名前空間方針に沿わせる。

## 7. 操作仕様

### PC

- `WASD`: Ground移動
- `Shift`: 高速移動
- マウス: 視点操作
- `F`: Ground ↔ Overview の高速切替
- Overviewでは既存Cesium操作を使用
- UIボタンからも同じ機能を実行できること

### モバイル

- Groundでは現行のMOVE/CAMERA二系統操作を維持・改善する。
- 「飛ぶ / 降りる」主要ボタンを常時アクセス可能な位置に置く。
- ボタンはsafe-areaを考慮する。
- 移動スティックと視点スティックの同時タッチを維持する。
- 遷移完了後、指を置き直さなくても次の入力が正常に認識されること。

UI文言は日本語を基本とし、「地上」「俯瞰」「飛ぶ」「降りる」等、意味が直感的に分かるものとする。

## 8. 軽快さ・レンダリング最適化

### 8.1 フレームレート目標

- 近年のデスクトップ: 通常操作で概ね `45 fps` 以上を目標
- 近年のiPhone/iPad: 通常操作で概ね `30 fps` 以上を目標

端末差・通信差があるため絶対保証値ではないが、遷移中に明確なカクつきや数百ms級のUI停止を発生させない。

### 8.2 既存最適化の維持

`immersive-gis.js` にある、移動中に3D TilesのSSEを緩め、停止後に品質を戻す設計は維持・活用する。

必要に応じてFlight/Overview遷移中は一時的に描画品質を軽量側へ寄せ、停止後に復元する。ただし建物・地形・ハザードが消失したように見える極端な設定は禁止する。

### 8.3 入力ループ

Groundの移動はレンダーフレームと整合した `requestAnimationFrame` ベースを優先する。既存30Hz制御を残す場合でも、カメラ表示が30Hzに固定されて低応答に見えないようにする。

標高更新・リスク判定・UI更新等の低頻度処理と、入力・位置・カメラ更新の高頻度処理を分離する。

## 9. 防災GISとして保持すべき条件

本機能は演出目的だけではなく、防災情報の空間理解を改善するためのものとする。

以下を必ず保持する。

- PLATEAU建物位置・属性
- 洪水、津波、土砂等のハザード表示
- 建物別リスク表示
- 3D水面等の既存機能
- 背景地図切替
- 出典・注意書き
- 地形高・ジオイド補正の既存ロジック

視点遷移によってハザードレイヤ、透明度、建物色、選択中シナリオ等が初期化されてはならない。

## 10. アクセシビリティ・酔い対策

高速なカメラ運動を行うため、`prefers-reduced-motion: reduce` を検出した場合は遷移時間を大幅に短縮し、過度な飛翔アニメーションを抑える。

通常設定でも、ロール回転は原則使用しない。不要な揺れ、バウンド、FOVの急変は行わない。

## 11. 実装候補ファイル

主な対象は以下。

- `docs/app.js`
- `docs/walk-mode.js`
- `docs/immersive-gis.js`
- `docs/index.html`
- `docs/style.css`
- 新設候補 `docs/navigation-controller.js`

必要最小限の変更に留め、既存のデータ生成・分析パイプラインには不要な変更を加えない。

## 12. QA / Acceptance Criteria

次をすべて満たして初めて完了とする。

1. Groundから1操作で飛翔し、約1秒で斜め俯瞰へ移行できる。
2. Overviewから画面中央の地表へ1操作で降下できる。
3. 離陸・着陸に目立つ瞬間移動がない。
4. headingが不自然に反転しない。
5. 着地直後からGround移動でき、walk stateとcamera positionがずれない。
6. PCのWASD操作が松山城3D散歩と同等以上に即応する。
7. モバイルのMOVE/CAMERA同時タッチが動作する。
8. モバイル全倒し移動が明確に軽快で、過大なデッドゾーンがない。
9. ハザード種別、透明度、背景地図、建物リスク色等がモード切替で失われない。
10. 遷移中も致命的なフレーム停止がない。
11. `prefers-reduced-motion` 時の代替挙動がある。
12. 既存validationおよびJavaScript構文チェックが通る。
13. 主要な新しい状態遷移を自動テストまたは再現可能なブラウザQA手順で検証する。
14. iPhone相当の狭幅viewportとデスクトップviewportの双方でUIが重ならない。
15. GitHub Pages上の実公開物で最終確認する。

## 13. 最終的な体感目標

ユーザーが地上で危険箇所を確認し、ボタンを押すとその地点から一気に上空へ飛び、浸水域や周辺建物の広がりを把握し、別の地点を見つけてそこへ降り、直ちに歩き始められること。

「地上モード」と「地図モード」が別アプリのように分断されるのではなく、一つの連続した3D空間として感じられることを完成条件とする。
